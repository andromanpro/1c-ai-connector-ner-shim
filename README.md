# Сервис распознавания имен для ИИконы

Дополнение к контролю персональных данных ИИконы 1.6. Сама ИИкона находит ФИО с отчеством или
инициалами, ИНН, СНИЛС, карты, паспорта, телефоны и почту. Для остального нужен разбор языка:
одиночные фамилии, имя без отчества, организации, адреса, даты рождения. Это делает
[Natasha](https://github.com/natasha/natasha) (MIT) в этом сервисе, рядом с 1С.

```
1С (КИИ_КонтрольПерсональныхДанных) ──POST /detect {text}──▶ сервис :9002 (Natasha)
                                    ◀── {entities: [{type, text, form, gender}]}
```

Модели Natasha зашиты в пакет: сервис работает без интернета, текст из контура не уходит. Тексты
запросов в лог не пишутся.

## Что находит

| Тип | Правило |
|---|---|
| ФИО | имена людей, в том числе одиночная фамилия и имя без отчества; порядок частей и род отдаются в `form` и `gender`, чтобы подстановка повторила форму |
| ОРГАНИЗАЦИЯ | только с правовой формой (ООО, АО, ИП…): это клиенты; «Microsoft» или «1С» без нее — вендоры |
| АДРЕС | части адреса склеиваются; нужен хотя бы улица или дом — город один персональными данными не считается |
| ДАТАРОЖДЕНИЯ | дата рядом со словами «рождения», «д.р.», «г.р.»; даты документов не трогаются |

## Запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/) либо Docker. Получите исходники:

```
git clone https://github.com/andromanpro/1c-ai-connector-ner-shim.git
cd 1c-ai-connector-ner-shim
```

**Разработка / файловая база** — тот же компьютер, что и 1С:

```
uv sync
uv run python shim.py
```

**Docker** (Linux-хост в контуре):

```
docker build -t iikona-ner-shim .
docker run -d --name iikona-ner-shim --restart unless-stopped -p 127.0.0.1:9002:9002 iikona-ner-shim
```

Параметры окружения: `NER_HOST` (по умолчанию `127.0.0.1`, в контейнере `0.0.0.0`), `NER_PORT` (9002),
`NER_MAX_CHARS` (200 000 символов на запрос). Текст длиннее лимита не обрезается, а отклоняется с кодом 413:
успешный ответ всегда значит, что проверен весь текст, а 1С считает отказ недоступностью сервиса.

⚠ Сервис не требует аутентификации. Держите его на `127.0.0.1` рядом с 1С; если он на отдельном хосте —
закройте порт firewall'ом так, чтобы к нему ходили только серверы 1С.

## Подключение в 1С

Обработка «Контроль персональных данных» → группа «Сервис распознавания имен (Natasha)»: адрес
(`http://127.0.0.1:9002`), таймаут, флажок «Без сервиса не отправлять». Кнопка «Проверить сервис»
спрашивает `/health`. В «Что искать» включите организации, адреса и даты рождения.

Если сервис не ответил: без флажка проверка идет только правилами ИИконы, в журнале регистрации
остается предупреждение; с флажком запрос не отправляется. Флажок действует в режимах канала
«Заменять подстановками» и «Не отправлять»: в «Только записывать в журнал» запрос уходит как есть,
а в режиме «Выключен» сервис не вызывается вовсе.

## Эндпоинты

- `GET /health` → `{"ok": true, "service": "iikona-ner-shim", "version": "1.6.0"}`
- `POST /detect` `{"text": "..."}` → `{"ok": true, "entities": [{"type", "text", "start", "stop", "form", "gender"}]}`

## Тесты

```
uv run python test_shim.py
```

Проверки распознавания (склейка имени, порядок частей и род, одиночная фамилия в падеже и ее род,
организация с правовой формой и без, адрес одной сущностью, город без улицы, дата рождения и дата
документа, эмодзи) и протокола через настоящий HTTP-сервер: текст длиннее лимита, тело не объектом,
отрицательная длина.

Красная проба тестов — `uv run python mutants_shim.py`: каждый мутант возвращает известную ошибку, и
тесты обязаны упасть.

Словари pymorphy2 обнаруживаются через стандартный `importlib.metadata`. Сервис не устанавливает устаревший setuptools ради `pkg_resources`. Распознавание, HTTP-протокол и красные пробы проверяются в GitHub Actions на Python 3.11 и 3.14, Windows и Linux.
